The user acceptance test script, as written

5,987 automated tests were passing when this was written, and it was still not enough. Tests prove the software does what it was told, not whether a day’s work can be finished or the numbers are right. This script asks that: 32 steps on real books, run by her, not me.

Translated from the Vietnamese original, committed 2 August 2026 at c1b6441. Reproduced as written: blank, not a completed run.

Why it exists. Different questions need different evidence.

Who runs it. The chief accountant, on real data from a company she keeps books for. Not me. The person who built it should be the last one deciding whether it works.

The dates do not run in textbook order. The software went into real use on 29 May, the day after I started it, and grew a screen at a time as the accountant used each one. This script came nine weeks later, when “she has been using it” no longer answered “does it work”. A script written before any code tests a guess; this one tests what was built.

The record block at the end stays blank here. A signed result would show one company passing on one day; the script shows what I thought was worth checking before anyone could call it ready.

How each step is graded

Every step has a measurable criterion, not whether it "seemed fine".

GradeMeans
PassFinished, figures match the criterion, no one had to be asked.
Pass with frictionFinished, but hard, slow or confusing. Say which.
FailCould not be done, or the figures are wrong, or someone else had to be asked.

One fail in Group A or B stops the release. Groups C and D do not block, but every result is recorded. A step marked [POSTS] changes real data, so the run starts with a backup.

Group A · The life of one invoice (blocks release)

#TaskPass criterion
A1Load one sales invoice XML fileAppears in the list; every amount matches the PDF to the dong.
A2Load the same file againReports a duplicate; does not create a second invoice.
A3Open the invoice detailAll present: number, series, date, buyer, tax number, every line item, tax rate, total.
A4Post that invoice [POSTS]Entry in the journal, debits equal credits, dated the invoice date.
A5Press Post againNo second entry.
A6Undo the entry just posted [POSTS]Entry disappears, invoice returns to unposted. Activity log records the posting and the undo.
A7Post it again against a project [POSTS]Project costing shows revenue and cost against that project.

Group B · Cash, receivables, inventory (blocks release)

#TaskPass criterion
B1Raise a cash receipt [POSTS]Cash book rises by the right amount; statutory receipt form prints.
B2Print that receiptActivity log records the printing.
B3Load one month of bank statementLines read equals lines in the file; no line is swallowed into a zero.
B4Match one receipt against an invoice [POSTS]Invoice moves to Paid; receivable falls by the right amount.
B5Open ReceivablesTotal equals the sum of unpaid invoices; one customer opens to show each invoice.
B6Add a new stock itemCost-of-sales account fills in from the group chosen, still changeable by hand.
B7Change its group to Finished goodsCost-of-sales account changes with it, not left stale.
B8Receive stock from a purchase invoice [POSTS]Stock on hand rises by the right quantity; value matches the invoice.
B9Issue more stock than is on handWarns immediately, not in silence.
B10Run the period-end cost transfer [POSTS]Cost-of-sales entry appears and matches the stock movement report.
B11Try the transfer while a stock item is negativeBlocked until a written reason is given.

B11 is not a technical rule but the option the chief accountant chose on 31 July, from three ways of handling negative stock I put to her. The document records it as her call, not mine.

Group C · Reports and tax returns (recorded, does not block)

#TaskPass criterion
C1Open the OverviewFive figures within two seconds. Amber reminder if the cost transfer has not been run.
C2Open the trial balanceDebits equal credits; opening balances match last year's closing.
C3Export the general ledger to ExcelFile opens; activity log records which report was exported.
C4Export the financial statementsTotal assets equal total equity and liabilities; legal citation printed in the footer.
C5Export the VAT returnFigures match the invoice listing for the same period.
C6Open that return in the real government filing softwareAccepted with no format error.
C7Export the purchase listing for company taxEvery required column present; the two that must not appear are absent.

Group D · Running it, and when things go wrong (recorded, does not block)

#TaskPass criterion
D1Press Back up nowNew file in the backup folder, not empty.
D2Press Rehearse a restoreReports a pass, and how many tables and rows it checked.
D3Switch to another company and backNo figures bleed across; the company name on screen always matches the figures.
D4Open the software on a phoneTables scroll sideways, text readable, buttons can be hit.
D5Pull the network cable, then press a posting buttonPlain error message in the user's own language, not an English crash screen.
D6Edit the same item in two tabsSecond person stopped and told to reload; first edit not silently overwritten.
D7Log in as a staff accountOnly assigned clients visible. Owner-only pages refused with an explanation, not a blank screen.

When this script stops being valid

Run it again whenever the posting, inventory or tax code changes, the database structure changes, a tax circular or statutory form changes, it moves to another machine, or it is restored from a backup.

A result belongs to exactly one version. The commit goes in the box above; old results are never reused for a new build.

Why I am showing this rather than describing it. My main page is screenshots of software. This is the other half of the job, the half the role is for: deciding what "working" means before anyone can argue, writing it down where someone else can check it, and naming the person whose call it was, not mine.
